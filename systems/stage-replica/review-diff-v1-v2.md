## 1｜本轮改了什么，为什么只改两项

brief 要求 V2 至少修改 **构图面积 / 状态节奏 / 观看关系** 中的**两项**。本轮的取舍写在 `review-v1.md` §6：

**改：** ①观看关系 ②构图面积　**明确不改：** ③状态节奏。

**不改节奏的理由：** 只跑过一次 V1。若同时改内容形态与时间结构，就无法判断改善来自哪一项。节奏留到下一轮单独处理——这是**可归因性**的要求，不是遗漏。

## 2｜改动一：观看关系（回应 review 的首要发现与 P4/P5）

### 2.1 媒体窗口改为**跟随观看者**（主要改动）

**V1 的问题：** 方位原点固定在世界坐标的"正面"。Dome 没有单一正面，于是不在正中的人看到的是空壳——`STAGE_LOOKBACK` 在 FULL_FIELD 时几乎全黑。

**V2 的做法：** 新增 `uAzCenter` uniform，每帧由 **program 机位的朝向**算出方位原点；着色器中所有方位计算（覆盖带、窗口、母版映射）改用**相对方位** `azRel`。

**效果（同一机位、同一状态、同一模式）：**

| 指标 | V1 | V2 |
|---|---|---|
| `STAGE_LOOKBACK` @ FULL_FIELD，画面点亮面积 | **21.0%** | **87.9%** |

### 2.2 Program 视角真正让画面占满视野（review 首位发现）

**V1 的问题：** `AUDIENCE_CENTER` 在 (0, 1.6, 12) 看向 (0, 3, 0)，视场里地板与舞台占下方约 40%——本 Demo 的论点"画面占据整个视野之后"从未被演示。

**V2 的做法：** 机位改到 (0, 1.6, 10)，目标抬到 (0, 5.5, −2)，fov 62 → 66（`AUDIENCE_LEFT` 同步）。这是"观众抬头看穹顶"的取景，performer 与 5 m 比例尺仍留在画面下缘作为尺度依据。

| 指标（画面点亮面积，已扣除 HUD 与角标） | V1 | V2 |
|---|---|---|
| FULL_FIELD | 69.7% | **84.8%** |

### 2.3 第二个尺度锚点

**V1 的问题：** performer 在 Program 视角只有约 30 × 97 px，一个锚点撑不起尺度（review 的 F4）。

**V2 的做法：** 观众侧三个 **1.7 m 参考立柱**（−3.5/6.5、3.5/6.5、0/10.5），冷色细线。**这是尺度标记，不是观众模拟**——brief 明确不做人群模拟，但"人物尺度参考"是硬要求。角度更正的 viewer 现在能在 `STAGE_LOOKBACK` 里同时看到立柱与 5 m 比例尺。

## 3｜改动二：构图面积（回应 P1/P2）

### 3.1 HORIZON 抬高可读面积与亮度

| | V1 | V2 |
|---|---|---|
| elevMax | 17.2° | **24.1°** |
| azMax | 31.5° | **48.7°** |
| 亮度 | 0.34 | **0.46** |
| 穹顶表面覆盖 | 0.8% | **2.4%** |
| 画面点亮面积 | 3.4% | **5.7%** |

**诚实说明：** 提高了 3 倍，但 HORIZON **仍然是最稀疏的状态**——这是设计意图（"铺垫"）。它现在读得出"前方有一块内容"，但我不声称它已经"被解决"。

### 3.2 APERTURE 从柔边亮块改为有边界的开口

**V1：** `1 − smoothstep(0.55, 1.0, r)`，边缘化得很开，读成"发光方块"。

**V2：** 收紧为 `1 − smoothstep(0.82, 1.0, r)`，并加一圈 **rim**（`smoothstep(0.62,0.86) × (1−smoothstep(0.94,1.06))`）作为开口内缘。

**效果：** 现在是一个有明确边界与亮边的开口，performer 站在它前面，收束语义成立。画面点亮面积 4.8% → 7.4%（更集中、更亮，而不是更大）。

## 5｜改动的代价（不是白拿的）

1. **窗口跟随观看者 ⇒ 同一个 cue 在不同机位下画面内容不同。** 这是"给观众看的"必然结果，但也意味着 Program 切换会重置构图——导播需要知道这一点。**这是 V2 引入的新问题，记录在案。**
2. **窗口跟随观看者 ⇒ 四分屏里只有一个视角的窗口是正对的**（`uAzCenter` 是全局 uniform，按 program 机位计算）。预览格子里能看到窗口偏移。
3. **抬高取景 ⇒ 画面下缘地板变薄**，`floor` 与环形网格作为空间证据的可读性下降；performer 仍在画面内但更贴下缘。
4. **尺度立柱可能被误读为人。** 已用冷色细线与 1.7 m 高度区分，并在本文件与 README 里明确说明它不是人群模拟。

## 7｜V2 之后仍开放的问题

1. 窗口跟随观看者带来的**导播语义**尚未定义：cut 时是否应该重新对齐窗口、还是保持内容世界锁定？留待下一轮。
2. **节奏仍未验证**：4 × 8 s 是否合适，本轮刻意没动。
3. HORIZON 仍是最稀疏状态（2.4% 穹顶覆盖），是否够读取决于放映条件。
4. FULL_FIELD 的 lattice 仍在角度空间生成，读起来像 dome 线框（review 的 F6），未修。
5. 真实 16K 母版、16:9 之外的输入、跨设备 WebRTC 均不在 V1/V2 范围。
