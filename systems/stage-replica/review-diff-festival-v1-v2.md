## 1｜V2 改了哪三项（按裁定表）

brief 要求 V2 至少修改 **构图面积 / 状态节奏 / 观看关系** 中的两项。裁定表定了三项，全部执行：

| 轴 | 改动 | 对应 V1 评审发现 |
|---|---|---|
| **观看关系** | ① performer 与三角形平台移到两屏**之间**（z=−5.5，V 形喉部），不再是屏前 10 m；② 两屏内缘收到 x=±1.64 m，中央缺口 **8.9 m → 3.28 m**；③ 重排四机位：`DJ_FRONT` 现在同时看到 performer 与两屏内缘，`HIGH_WIDE` 明确标注为**技术机位**而非人眼 | B1 / B2 / B3 / B4 |
| **构图面积** | ④ 源改成 **2048×1024（2:1）**，与 18×9 m 屏幕一致，修掉 V1 约 12.5% 的横向拉伸；⑤ 跨缝地标从**对称椭圆**换成**非对称斜线**，使"合成"可被证明；⑥ 独立态让右屏**垂直翻转**并使用不同裁切，两块屏读起来确实是两块不同画面 | F / F / C |
| **状态节奏** | ⑦ 按 brief 实现 RELEASE 的"**一侧先退、中心保留**"：左屏先退，45% 进度后右屏再退，performer 始终居中 | D |

**另外两项声明与实现的对齐（不算设计改动）：**
- `fallback` 现在是真的**本地 loop**（一条持续移动的暗扫描条），而不是 V1 的"冻结 + 变暗"。
- 交付录屏改用 `?hud=0&quad=0` 单独出，不再把交互界面当成导播输出（V1 的 `v1-director-32s.mp4` 含 HUD 与四分屏，保留作为过程证据）。

## 2｜可测的改进

| 指标 | V1 | V2 |
|---|---|---|
| 两屏内缘间距（几何） | 8.9 m | **3.28 m**（−63%） |
| 中央暗带宽度（画面测量） | **77 px** | **44 px**（−43%） |
| 跨缝地标形状 | 对称椭圆（两半看起来像镜像） | **非对称斜线**（只有合成时才连成一条） |
| 源宽高比 | 1280×720（16:9，被拉伸到 2:1 屏） | **2048×1024（2:1）** |
| 角标宣称的 2048×1024 proxy | 未实现 | **已实现** |
| performer 相对两屏 | 屏前 10 m | **两屏之间** |
| `DJ_FRONT` 能否看到两屏 | 否（两屏都被裁出画外） | **是**（`stills/v2-dj-peak.png`） |
| RELEASE | 整体变暗（与 LOW 近似） | **左先退 → 右再退**（`stills/v2-release-late.png`，HUD 显示两侧退场百分比） |
| fallback | 冻结 + 变暗 | **本地 loop 持续运动**（`stills/v2-fallback.png`） |

**中央暗带的测量方法：** 在 1600×900 画面上取 y∈[360,560] 的横带，排除 HUD（x<400）与角标（x>1150），统计内容区内部最长的连续暗段。V1 评审用另一套方法（直接求两屏内缘的投影位置）得到 168 px；两者口径不同，不应混用，此处只用于 V1↔V2 同口径对比。

## 3｜为什么"非对称"是关键

V1 的地标是一个**对称椭圆**：合成时两屏各持一半，但两半看起来像互为镜像，于是"这是一张画被切开"只能靠 HUD 文字断言——评审正是这么说的。

V2 换成**一条跨 u=0.5 的粗斜线**（外加一条更细的平行偏移线与一个偏心方块）：
- **合成时**，左屏是斜线的左下段、右屏是右上段，两段**共线**，跨过 3.28 m 缺口仍读作一条直线；
- **独立时**，左屏有完整斜线，右屏因垂直翻转 + 不同裁切而呈现另一套走向。

对称图形可以被"两块各有一个相似形状"解释；非对称的共线图形不行。这是把"合成一个整体"从**断言**变成**可证明**的关键。

## 4｜代价与新问题（不掩饰）

1. **中央 3.28 m 的缺口依然存在**，而且从 `DJ_FRONT` 看是一片纵长黑带。两块墙之间站着人，本来就不可能无缝——所以 PEAK 的判据应表述为"**构图跨缝连成一体**"，而不是"像素连续"。这条在 V1 就记录过，V2 缩小了它但没有消除，也不应该消除。
2. **两屏在 V 形深处更靠近，意味着侧后方观众看到的内夹角更窄**：`STAGE_LEFT` 视角下两块屏的透视压缩更明显。
3. **源变成 2048×1024 后每帧绘制成本约 4 倍于 1280×720**，实测抓帧率从 59.98 fps 降到 46.04 fps（录屏时的 CDP 抓帧率，不是页面 rAF）。仍在可用范围，但这是这次改动引入的真实代价。
4. **右屏垂直翻转是"独立"的廉价表达**。它确实让两屏读起来不同，但严格说这是同一素材的镜像变体，不是第二条源。brief 允许"同一 source 通过 crop / UV / offset 形成两种构图"，所以不违反要求；若要真正两条源，属于下一轮范围。

## 5｜明确没改的

- **cue 总长 32 s** 与每状态 8 s（节奏问题只按 brief 修了 RELEASE 的形态，没有重排时间结构）。
- **四状态的命名与顺序**（LOW / BUILD / PEAK / RELEASE）。
- **四机位名称**（FOH_WIDE / DJ_FRONT / STAGE_LEFT / HIGH_WIDE），只改了位置、朝向与 fov。
- **proxy 尺寸体系**（44×20 舞台、18×9 屏、内旋 18°、6×4 平台），除宽高比修正外未动。内旋角仍是自定的。
