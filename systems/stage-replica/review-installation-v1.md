# 第一部分｜评审报告（构建者记录）

## A. 结论

**does not hold up — as the test it claims to be.**
参考/proxy 纪律与房间、投影几何都是正确的，但**这个 Demo 自己的前提（少量素材通过尺寸、观看距离、声音与持续时间成为完整现场）没有被真正检验**：没有声音；观看距离只改变缩放；持续时间是"4 次 ramp + 每段 8 秒静止 + 每 6 秒整场重排"；而且 AFTERIMAGE 状态携带一个真实的渲染瑕疵，并在交付录屏里与丢源演示叠在一起。

它先做了来源一致性检验：线上 `main.js` / `scene.json` 与本地 sha256 一致；5 张交付静帧中 4 张与它自己独立渲染的结果逐字节一致。

## B. 主要发现

**B1｜AFTERIMAGE 把静态元素累积成一条横贯墙面的硬直线——这是渲染瑕疵，不是余像。**
- 机制：每帧都会重画"中间那条 1px 横线"与底部条，而在淡出合成下（每帧只减 5.5%）它们**不会被清掉而是累积**。
- 实测：`?t=42&view=CENTER` 时源图 y=450 行（投影面的垂直中心）亮度均值 **20.807**、min 20.8、max 20.8、frac>10 = **1.000**——整行完全均匀；同位置 `?t=18` 为 2.86、`?t=30` 为 2.93。录屏中该行 t=44 为 9.99，而 t=20 为 0.58、t=28 为 1.08。
- 这是几何差异，不是审美：它只在一个状态出现，其余三个状态都没有。

**B2｜AFTERIMAGE 其实是"被压暗的 SPARSE"；没有残留可见，而且切换是阶跃不是过渡。**
- `residual` 只在 `> 0.5` 时切换合成方式，`evaluateCue` 里的"blend"从未真正混合；0.055/帧的淡出在 60fps 下半衰期约 0.2 秒，而布局每 6 秒才重排一次，布局内几乎不动，**没有东西可以拖尾**。
- 实测点亮面积（扣掉 UI，>8/255）：SPARSE **0.688%**、ACCUMULATE **1.331%**、DENSE **3.129%**、AFTERIMAGE **1.000%**；峰值亮度 46–50 / 148 / 203 / 48–51。AFTERIMAGE 更接近 SPARSE 而不是 ACCUMULATE。

**B3｜观看距离只改变取景——没有东西可供"距离"起作用。**
- 材质是固定 **1280×720** 画布映射到 10.24×5.4 m = **125 px/m**，不是声明的 4096×2160（400 px/m）；`scene.json` 的 `raster.master` **从未被 main.js 读取**。
- 投影面包围盒实测：CENTER **1428×692 px**、FAR **708×360 px**（比值 0.496 / 0.520）——正好一半，内容、亮度、可读性都没有变化。

**B4｜「墙 + 地面」是同一张画的第二份拷贝，而且从 Program 机位看是零像素。**
- 两个材质共用同一个 texture 对象，地面是**完全相同的图像**；地面 z ∈ [−6.7, −1.3]、墙在 z = −9，中间有 **2.3 m 未打光的缝**、没有连续性。
- `?t=30&floor=0` vs `floor=1` 在 CENTER 下做差分：差异**只出现在 HUD 面板内部**（就是按钮文字），UI 之外的 3D 渲染**逐位相同**。在 FLOOR 机位才有约 127 px 的变化带（占 900px 画面的 14%），且被画面下缘切掉。

**B5｜黑盒在 Program 机位读作空洞；场景里唯一的尺度物从不入画。**
- CENTER（z=−3，6 m，fov 58°）可见宽度 11.8 m、房间宽 14 m，房间边线基本在画外；FAR 才勉强成线框；LEFT/FLOOR 反而成了"被匀光照亮的灰房间"，不是黑盒。
- 5 m 白色比例尺（位于 z=+2）在 CENTER/LEFT/FLOOR 三个机位都在**相机身后**；在 FAR 也低于视轴约 65°（半垂直视角 29°）。实测五个机位画面里 **0 个近白像素**。
- `performerHeightM` / `eyeHeightM` / `viewerNearM` / `viewerFarM` 在 main.js 里**从未被读取**。

**D. 持续时间**（从 48 秒录屏按 2fps 采样、裁掉 HUD 后逐帧平均 |Δ|）
- 全片 |Δ| 中位数 **0.019**。SPARSE 段 t=0–12：几乎完全静止、且接近全黑。
- ACCUMULATE / DENSE 各自只在 4 秒 ramp 内变化，随后 **8 秒平坦**。
- **全片最大的两次变化是 DENSE 里每 6 秒的整场重排**：|Δ| = **3.528**（t≈29.5s）与 **3.426**（t≈35.5s），**比状态切换本身（t≈24 的 0.954）还大**。在一个明确禁止"快速导播"的 Demo 里，最大的视觉事件是这次"剪切"。
- AFTERIMAGE t=40–47：|Δ| ≤ 0.036，是**八秒冻结**。

## C. 状态区分（它的测量）

| 状态 | 占画面 >8 | 亮点游程数 | 峰值 |
|---|---|---|---|
| SPARSE | 0.69% | 37 | 46 |
| ACCUMULATE | 1.33% | 487 | 148 |
| DENSE | 3.13% | 1994 | 203 |
| AFTERIMAGE | 1.00% | 193 | 51（另有整行均匀线） |

**四个状态确有差异，但只是同一个随机场的数量差异**：用同一个 `pseudo()` 计算跨 6 秒重排的保留率，SPARSE ≈2%、ACCUMULATE ≈14%、DENSE ≈43%（44.6% 占用下的随机水平）、AFTERIMAGE ≈3.5% —— **没有任何元素在状态之间延续**。所以 ACCUMULATE 并不"累积"，AFTERIMAGE 也没有可供留下余像的东西。

## F. 未被支持的说法 / 与画面不符的数字

1. **HUD「DENSITY 58.0% 规则格」**：`createSource` 以**有放回抽样**取 `round(0.58·64·36)=1336` 次，实际点亮的**不同**格子只有 **1027 = 44.6%**。全部：2.00% / 14.63% / 44.57% / 4.95%。它把生成器参数当成占用率显示，且即便按参数算也偏高约 30%。
2. **status.json 的「密度 2% / 16% / 58%」与「已提到 58%」** —— 实际到不了 58%。
3. **status.json 说「CENTER 与 FAR 的差别只有在连续播放时才读得出」** —— 没有任何交付物证明这一点：13 个采样帧里 CENTER 按钮始终是选中态，地面按钮始终关闭，录屏是**一个固定机位**。
4. **`&hud=0|1` 写在 main.js 头部注释里，但没有实现**：代码里没有 `params.get("hud")`，带不带该参数画面逐字节相同（t=42 仅 1 像素、maxdiff 3 的渲染噪声）。
5. **UI 说「4096×2160 由已确认的 DCI-4K 器材换算」**：数字来源是真的，但**没有任何渲染是 4096×2160**；运行时画布是 1280×720，`raster` 字段从未被读取。
6. **宽高比**：源 1280×720（1.778）映射到 10.24×5.4 m（1.896），横向拉伸 **6.7%**；交付视频又是第三种比例 1578×802（1.967）。声明、渲染、屏幕、录屏**四者没有两者同比例**。
7. **音频**：main.js 头部把"声音"列为四个变量之一，status.json 的问题也包含声音，但**没有任何音频**（mp4 只有 h264 视频流；无 audio 元素、无 Web Audio）。**status.json 已自行声明这是已知缺口**，属"声明的缺口"而非"过度宣称"。
8. **`?t=30&drop=1` 得到黑墙 + OFFLINE**，而 `?t=30&dropAt=20` 才是预期的 ~50% 亮度 FALLBACK —— 文档化的 `drop=1` 单独使用**不能**复现 fallback 画面。

它同时明确指出**做对的地方**：confirmed/proxy 分离是它见过最严谨的（reference.md §3、status.json 的 proxy 表、画面上的安静角标三处一致，且把房间、观看距离、地面投影标为 proxy，把 10.24×5.4 与 DCI-4K 器材作为逐字引用、4096×2160 标为换算）；以及"暗房里不画边就看不出投影边界"这一点确实被解决了（边框线实测约 26/255，可见）。

# 第二部分｜构建者裁定（LEAD / BUILD）

## 1｜结论：接受

**我接受「does not hold up — as the test it claims to be」这个判定。** 这不是措辞问题：这个 Demo 的问题不是它声称的那个问题。brief 给它的职责是证明"少量素材 + 尺寸/距离/声音/持续时间可以成为完整现场"，而我做出来的东西**没有真正测试这四件事中的三件**。

它这次**没有一条需要否证**（Sphere 那次有一条弧度/角度混淆、Festival 那次是"镜像 vs 互补"的措辞细化）。这次我逐条复核，全部成立。

## 2｜已确认的根因（都是我的实现问题）

| # | 根因 | 性质 |
|---|---|---|
| B1 | 淡出合成下**每帧重画静态线条**，必然累积饱和 | 我的算法错误 |
| B2 | `residual` 只在 >0.5 切换；淡出半衰期 ~0.2s，而内容 6 秒才动 → 无可拖尾之物 | 我的设计错误 |
| B3 | `raster.master` 声明了却从未读取；画布 1280×720 → 125 px/m，距离无事可做 | 声明与实现脱节 |
| B4 | 地面与墙共用同一 texture；两个面不在同一坐标系统 | 我的设计错误 |
| B5 | 比例尺放在相机身后 / 视轴下方 65°；房间边线在画外；尺度字段从未被读取 | 我的摆放与接线错误 |
| F1 | DENSITY 显示的是生成器参数，且有放回抽样使它比参数还高 | 我的标注错误 |
| F4 | `hud` 参数写在注释里但没实现 | 我的文档谎言 |
| F7 | `drop=1` 在晚期时刻把 fallback 压到近乎全黑 | 我的状态机问题 |

## 3｜V2 范围（回应"不是它声称的那个测试"）

brief 要求 V2 至少改 **构图面积 / 状态节奏 / 观看关系** 中的两项。这里必须动三件更根本的事：

| 轴 | V2 要做 |
|---|---|
| **观看关系** | 重排 CENTER/FAR/LEFT/FLOOR 的取景，让**地面与房间边线进入画面**；把 5 m 比例尺与一个已知高度的参照物放进所有机位；让 6m↔12m 的差别作用在**细节与视场压力**上，而不是单纯缩放——这要求源本身有更细的空间频率（见下） |
| **构图面积** | 源改为与 10.24×5.4 m 一致的 **4096×2160（1.896:1）或等比例 proxy**，修掉 6.7% 拉伸；**地面投影与墙面必须共享同一坐标系统**（边缘对齐或镜像延续），否则它不是"空间化"而是第二块屏；HUD 的 DENSITY 改为报告**去重后的实际占用** |
| **状态节奏** | 重写 AFTERIMAGE：**真正的余像**需要"先有、再残留"——改为累积缓冲（保留上一布局并缓慢衰减），且静态装饰线不得在残留模式重画；**取消每 6 秒的整场重排**（brief 明确禁止快速剪切，而它现在是全片最大的视觉事件）；让 ACCUMULATE 真的**累积**（保留上一布局的元素而不是重新抽样） |
| **声明对齐** | 实现 `?hud=0`；`drop=1` 必须能单独复现可读的 fallback；要么实现 4096×2160，要么把 raster 声明改成事实 |

**声音**：brief 只要求"可以播放"，而 status.json 已声明未实现。V2 的诚实选择有两条——要么加一条**可选**音轨（默认静音，不参与无头录制），要么把 Demo 的问题表述改成不依赖声音。我倾向前者，但**不会声称它已被检验**，除非真的有人在现场听过。

## 4｜这一轮最值得保留的东西

评审真正指出的是**方法论问题**：我一直在优化"画面能不能看"，而这个 Demo 要求的是"**这四个变量能不能被证伪**"。Sphere 与 Festival 的变量是空间与构图，看画面就够了；Installation 的变量是时间与距离，**必须靠测量**。B3 的"距离只改变缩放"正是用测量才暴露出来的——这一点会带进 V2 的验收方式：**每个状态都要给出可测的变化量，而不只是"看起来不一样"**。
