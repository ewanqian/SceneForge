# 超自然工坊建设档案｜2026-11-26

**这是 SceneForge 的 LED 屏幕与舞台预演技术档案。** 首轮参考证实屏幕规格和使用分区；V0.2 又对照六张照片纠正空间关系，建筑几何仍不是实测；现场照片、内部演出素材和临时素材链接不进公开仓库或 Pages。原图保留在项目所有者的私有资料夹。

## 01｜锁定屏幕

| 用途 | 像素 | 说明 |
|---|---|---|
| 正式全屏（默认） | **6540 × 1824** | 画幅 **3.5855:1**，用于全屏主视觉/演出 |
| 二分屏校准 | 3270 + 3270 | 分界 x=3270，输出仍是完整栅格 |
| 三分屏校准 | 1647 + 3246 + 1647 | 分界 x=1647 / 4893；中区近似 16:9 |
| 物理屏 | **12.16 × 3.42 m** | 约 **3.5556:1**；用作舞台物理尺寸而非像素尺寸 |
| 16:4 排练容器 | 4:1 | 可装原生内容但需留白；不是送屏规格 |

以观众视角自左向右排列。技术页列 P1.8、亮度 ≥700 cd/m²、面板刷新 ≥3840 Hz、对比度 ≥4000:1、视角 H≥160°/V≥140°，为资料中的标称信息，**不是素材帧率、现场电平、亮度设置或验收实测**。六张照片中的中间亮区是软件投在黑色 LED 上的内容窗，亮窗左右黑像素仍属于 LED；内容中弯曲并不证明物理屏弯曲。V0.2 用一块平面，屏两端直接贴侧墙内表面，不留材质边条；尚不能据图确定曲率、物理分段或展开宽度。

[机器可读屏幕配置](led-profile.json) 是独立屏幕配置，不是可直接传给 `venueManifestSchema` 的场地对象。另附 [`venue-manifest.draft.json`](venue-manifest.draft.json)，按实际 v1 schema 写的**未注册**平面灰盒。屏体 12.16 × 3.42 m 是参考值；V0.2 替代 15 × 18 × 5.5 m 旧示意：两面侧墙内净宽按屏幕 12.16 m 对齐，深高 11.2 × 3.9 m、屏底近地、平面曲率=0、各机位均为照片辅助的占位，不是实测。正看屏幕右侧为通高卷帘窗和暖木墙裙，左边浅色实墙；落地呈现，无固定高台，显式保留可移动讲台/桌椅与裸露顶。Windows 验证后，把 JSON 内容放入 `src/data/venues.ts` 的 `manifests` 数组，由 `src/domain/scene.ts` 的 `venueManifestSchema.parse()` 入库；`npm run verify` 后运行本地预览，与原生栅格测试一起复核。参照 repo 的 `src/components/VenueScene.tsx`：box 布局使用平面。若采用目录默认 BoxShell，现有的 0.3m 侧墙以 ±`width/2` 为**墙体中心**，会吃掉屏两端各 0.15m；V0.2 的约束却是**墙体内面**位于 ±6.08m。原生注册前，应让墙沿厚度各向外移 0.15m（仅该场地或按开关），或使用审核过的 V0.2 GLB；不要缩窄 LED。双/三分屏属于程序分区，勿伪造多个施工屏面。不要升级为 `surveyed`。

## 02｜Windows / Blender 任务交接

V0.2 已在云端制作并重开校验：Blender 和 GLB 两侧接缝差均小于 0.01 mm、UV 四角正确；原生场地 fixture 经当前 SceneForge Zod schema 解析。制作用二进制与参照图均为私有交付，不随本草稿 PR 上线。

1. 先留存原始附件，再做可编辑 `supernatural-stage.blend`。米制 1 单位=1m；聚焦屏幕、地面、台面和人物参照，再做环境。定义 `LED_SCREEN`、`STAGE_FLOOR_LEVEL_GUIDE`（仅地面标记，无高台）、`FOH_CENTER`、`FOH_FAR`、`STAGE_LEFT`、`PERFORMER_EYE`。从现场图恢复空间关系即可；房宽深高、观众点位、屏底高、偏移、曲率/分段全部标 **proxy** 或留空。不是施工测量，未量尺寸不能靠照片升级为已确认。
2. 单屏程序用独立网格/材质，表面面向观众；Blender 内定位 UV 左右和上下。网络端素材以左上为像素原点，所有映射先以四角编号实测一次，不默认 Blender 与浏览器纹理 v 方向一致。若分段，按实际相邻屏节点做连续 U；如果现场仅给物理宽度而不知柜体/发卡顺序，则暂用平面连续 U，不把内容模式分缝当硬件分缝。
3. 输出小体积 `supernatural-stage.proxy.glb` 与相机/屏幕坐标说明。运行时替换屏面视频材质，不把 LED 像素网格烘焙进 glTF。上传前在 SceneForge 预览，从台前、最远观众位和表演者视角复核；如 GLB 无法加载，回退到尺寸一致的平面屏，不阻断排练。
4. 私有二进制交付到所有者可控的托管/资料目录；公共 `public/` 只放已批准的模型与自制媒体。工作回执至少含日期、分支/提交、实测和 proxy 清单、参考与 GLB 版本、三个机位截图、UV 正反和比例结果、可复现的打开方法。**不要**用新的 Blender 文件覆盖现有场地工作文件。

## 03｜Web 映射和验收

- 节点与材质：`LED_SCREEN`、独立 UV0、RGB 角标 `TL/TR/BR/BL`。程序原生输出保留 6540×1824；Web 预览可用等比 1635×456 或 3270×912，不因预览档变更源尺寸。手机兼顾可用性；桌面/Mac 与真实硬件分别记录。
- 适配默认 `contain`，明示留黑。需要裁切时启用 `cover` 并显示边界；**不把 full frame 拉成 16:4 或按现场物理比直接改色条像素宽度**。有现场处理器所有权的操作员才确认有效画布、显示映射、输入格式/帧率/色彩、余量和安全亮度。
- 用一份 6540×1824 诊断图：四角文字、中心靶、尺寸刻度、圆形/正方形、灰阶、红绿蓝，再按模式显示二分/三分边界。验收四角不反转、正确 0–100% UV、边缘不出框、媒体降档不改比例。现场拍照判断圆形一致性；不擅自以 0.84% 的物理/栅格偏差决定处理器补偿。
- 原型先走静态 HTTPS；媒体用有权素材的同源 URL 或 CORS 受控访问，支持 Range；本地视频用文件选择 + object URL，不能上传/外传。SceneForge 的 [现有 Pages 工作流](../../../.github/workflows/deploy-pages.yml) 在 `main` push 或手动触发时执行 `npm run verify`，打包发布 `dist/`。独立入口后续可用 `public/stage-replica/supernatural-workshop/index.html`（相对资源路径），构建后应映射为 `/SceneForge/stage-replica/supernatural-workshop/`；这是**拟定路径，不是已发布 URL**。演出练习站可先独立托管，部署验过后才回填其地址。NDI/OSC、真灯、真实内容时码、6.5K PLAYBACK 性能以及 Quest/Vision Pro 分别是单独验收，不是浏览器可开的同义词。

## 04｜把旧作品的操作变成新乐器

- **TIMER / 控时者**：提取“时基、暂停、继续、错相”的操作，把节奏不变时允许的小幅相位偏移做成可复位参数；不是复制已完成的作品素材。
- **Drop Flow / 滴流**：提取“身体的连续变化→残留→消散”的规则，用独立生成的点群先试位置/强度/衰减；未清授权的动捕、音轨和关联人员素材不得公开。
- 可并行制作多条候选，但固定同一个校准场景、可比较的 input/cue 接口、统一审片档位。先过可重复演奏与复位，再比较图像质量。能当作可调引擎的才接入场景；一次性视频可以留作离线备用，不冒称实时。
