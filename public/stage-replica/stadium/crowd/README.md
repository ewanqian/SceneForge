# Stadium / 360° — 观众席与视线（人群层）

**在线:** https://ewanqian.github.io/SceneForge/stage-replica/stadium/crowd/
**性质:** Stadium Demo 的人群层，不是第五种舞台。它把"95,000 人环绕"从一句话变成**可测量**的东西。

> **⚠️ V2（本页当前版本）由一次独立评审驱动。** 评审判定「holds up with caveats」，并指出六处实质问题——包括**让全部结论成立的那个参数从未声明**、**公布出去的静帧来自一个只画了 54% 人群的截断渲染**、以及**角标把参考并未公布的圆柱高度写进了「官方逐字」**。逐条裁定与修复见 §7。算术本身被独立复算并确认正确。

> ⚠️ **PROXY。** ⌀30m 圆形舞台与 ⌀20m 圆柱 LED 来自 STUFISH 官方逐字。**圆柱高度、观众席行距、升阶、座位间距、碗体全部是教学 proxy**——参考未公布任何观众尺寸，也未公布圆柱高度。

## 1｜三个可测量的东西

| 指标 | 怎么算 | 界面读数 |
|---|---|---|
| **人数 / 密度** | 逐排按弧长与座位间距铺位，扣掉横向通道（每 8 排）与纵向通道（每 28 座），再按目标密度确定性抽稀 | `PEOPLE 画出人数 / 可占座`、`DENSITY 实际 n 人/m²` |
| **逐排视线 C 值** | 从第 i 排眼位看向**焦点**，量它越过第 i−1 排头顶的垂直余量 | 底部逐排柱状图 + `C MIN` + `FIRST FAIL` |
| **遮挡** | 逐排判断还能不能看到**表演者头部 / 脚部 / LED 屏顶** | `遮挡 n/51 排完全看不到表演者` |
| **被包围感** | 从艺人位置（舞台中心、眼高 1.6m）量水平覆盖、人群的垂直张角、最近距离 | `ENCIRCLE` |

## 2｜视线焦点：这套计算里唯一"由人选定、却决定全部结论"的参数

V1 把焦点**隐式**取在碗体轴线（r=0）、高度 0m，而且从未在配置、README 或角标里声明横向位置。那是全场离每位观众**最远**的一点，并且比本页自己画出的台面（deck top y=1.60）还低 1.6m。

独立评审实测，换一个焦点，结论完全改变：

| 焦点 | 最小 C 值 | 首次不合格 |
|---|---|---|
| **舞台边缘（V2 默认）** r=15, h=1.6 | **−142.0 mm** | **第 2 排** |
| LED 屏面 r=10, h=1.6 | −100.2 mm | 第 8 排 |
| 碗体轴线 r=0, h=0（V1 的隐式选择） | −59.1 mm | 第 13 排 |

**V1 的头条数字是那个未声明选择的产物，不是这个碗体的性质。** V2 把焦点写成配置里的显式选项、做成界面上的按钮、默认取**观众真正在看的位置**（舞台边缘 + 台面高度），并把 V1 的取值作为"可复现旧结论"的第三个选项保留。

## 3｜这一层真正的发现：等升阶在后排会失效（而且是一个普遍事实）

用固定的升阶高度（0.45m）铺 52 排看台，C 值随距离衰减并最终为负——**后排的视线被前排头部挡住**。这个结论**看渲染图完全看不出来**。

页面同时**解算**出能保持目标的升阶剖面：

$$h_i = \frac{C - f + y_{i-1} + P - k\,(y_{i-1} + E - f)}{k},\qquad k = \frac{D_{i-1}}{D_i}$$

| 升阶模式（焦点取舞台边缘） | 最小 C 值 | 首个不合格排 | **完全看不到表演者的排数** |
|---|---|---|---|
| **等升阶 0.45m** | **−142.0 mm** | **第 2 排** | **7 / 51** |
| **按 C 值解算** | **60.0 mm** | 无 | **0 / 51** |

**但这里必须说清楚两件评审指出的、V1 说错的事：**

1. **"等升阶会崩塌"不是关于 0.45m 的发现，而是所有等升阶的普遍性质。** 解析上，等升阶的 C 值必然收敛到 `E − P = 眼高 − 头高`，本参数下是 **−160mm**，与升阶取值无关（数值验证：0.2 / 0.45 / 0.9 / 1.5m 在 4000 排后都收敛到 −152…−160mm）。0.45m 是按"让曲线有可读形状"选的。
2. **"第几排首次不合格"是判据的函数，不是场馆事实。** 判据取 30/60/90/150mm 时，首次不合格分别是第 18/13/9/3 排（焦点取碗体轴线时）。60mm 是本项目采用的值，**体育场通常取更大**。

## 4｜遮挡：C 值为负 ≠ "完全看不见"

C 值衡量的是**到焦点那一点**的视线。**"看不到焦点"和"看不到表演者"是两件事**，评审实测两者相差约 6 倍。所以 V2 直接算第二个：

以常升阶为例，51 排中（第 1 排无前排不参与）：

| 结果 | 排数 |
|---|---|
| **完全看不到表演者** | **7**（第 46–52 排） |
| 只看不到脚部 | 10（第 36–45 排） |
| **完全看不到 LED 屏** | **0**（第 52 排仍能看到 8m 屏的顶部 0.29m） |

**V1 的 README 第 6 节写的是"后排那 40 排人里有多少人其实看不到你"——那是错的，实际是 7 排。** 解算升阶之后是 **0 排**，这也正是那条曲线的真正价值。

## 5｜被包围感（**未截断**渲染实测）

从舞台中心、眼高 1.6m：

| 量 | 常升阶 | 解算升阶 |
|---|---|---|
| 水平覆盖 | 100% | 100% |
| 垂直张角 | 2.4° → 21.0° | **2.4° → 35.6°**（碗体更高） |
| 最近观众 | 18.4 m | 18.4 m |

**水平 100% 和"最近 18.4m"其实不说明什么**——把一群人铺成一个完整圆环，水平覆盖必然是 360°，而"最近"永远等于第 1 排的半径。评审因此指出：水平这一项是**构造保证**，不是测量。真正有信息量的是**垂直张角**，而它取决于碗体剖面。

> **V1 公布的三张静帧全部来自 `?cap=12000` 的截断渲染（只画了 12,000 / 22,215 人），却按未截断的参数打印 "2.5 人/m²"。** 有人据此复现出 README 里引用的 19.0°，而未截断值是 21.0°（常升阶）/ 35.6°（解算）。V2 的静帧**不再带 cap**，界面在实例被截断时会显示 **⚠ 已截断**。

## 8｜仍未做到 / 已知限制（不掩饰）

1. **容量是 2.2 万，不是 95,000。** 参考的 95,000 人由什么构成，**评审未能核实**，V1 里我写的"包含场地站立人群与 OAKA 既有看台"是**无来源推断**，本页不再这样断言。正确说法是：**这是一个 2.2 万座碗体的密度与视线研究**。
2. **场地站立区没有建。** 那部分有个值得讲的结论（平地上的人群会自己挡住自己），但只写了这句话。
3. **水平包围度与"最近距离"是构造保证**，不构成测量（§5）。
4. **人体参数是常量**，因此 C 值对**同一身高**的人群成立；真实场馆要按身高分位数算。同一页仍存在三个不同的人体高度取值。
5. **C 值只算垂直视线**，未算侧向遮挡、未算对屏幕中心与对舞台边缘的差别。
6. **观众无个体行为**（只有着色器轻摆）；坐姿模式只是把几何压扁 0.74，并没有真的建座椅。
7. **60mm 是选择**；判据敏感性见 §3。
8. 疏散/通行能力、轮椅席视线、声压都没做。

## 9｜复现

```bash
npm run build
python -m http.server 8123 --bind 127.0.0.1 -d dist
```

```
?view=BOWL_WIDE|STAGE_CENTER|ROW_20|TOP
?overlay=look|density|sightline|encircle
?density=sparse|normal|packed          0.6 / 1.5 / 2.2 人每平米
?posture=standing|seated
?rake=constant|sightline               等升阶 / 按 C 值解算
?focus=stage-edge|led-surface|bowl-axis 视线焦点
?cap=<n>                               限制实例数（无头抓图用；界面会显示「已截断」）
?probe=1                               把指标写进 DOM，供无头验证
```

  "http://127.0.0.1:8123/stage-replica/stadium/crowd/?probe=1&focus=stage-edge"

## 10｜这一层试图说明的一件事

**"很多人"不是一个人数，是一组几何关系。** 9.5 万这个数字本身不说明任何体验；说明体验的是：最近的人离你 18m、人墙在视野里升到多少度、以及后排那 51 排里究竟有 7 排看不见你——**而不是 40 排**。

这三件事里，前两件可以看，第三件**必须算**。而这个页面的第一次发布恰好证明了一件事：**连"算"也需要人来复核**——因为焦点取在哪里，是我自己选的，而我把这件事忘了写下来。
