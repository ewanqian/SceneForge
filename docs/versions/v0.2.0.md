# SceneForge v0.2.0 — Needle XR Room

Date: 2026-09-02  
Branch: `feat/needle-xr-room-v0.2.0`  
Status: experimental integration

## Purpose

Validate a shared spatial review room before adding any networking runtime to the main SceneForge viewer.

## Added

- Standalone Needle Engine 5.1.5 room at `public/needle-room/`.
- Named room URL (`?room=…`).
- Desktop screen/window capture through Needle `ScreenCapture`.
- Camera capture path, including the NDI Webcam Input / Virtual Input shortcut.
- Shared 3D 16:9 video surface using `VideoPlayer`.
- Vision Pro / headset WebXR entry via Needle `WebXR`.
- XR rig and deterministic stage origin.
- **Reset Stage** and **Screen Ahead** controls.
- Remote HTTPS GLB/glTF model loading.
- Local GLB loading.
- Optional custom Needle networking backend (`?networking=wss://…`).
- Research record for Vision Pro, live video, NDI and later self-hosting.

## Deliberately not added

- Needle Engine as a dependency of the primary React/R3F app.
- Direct browser NDI discovery/decoding.
- Shared model selection/transforms.
- Voice chat UI.
- User accounts/permissions.
- TURN configuration or fully offline LAN deployment.
- Vision Pro passthrough AR.

## Compatibility target

- Desktop sender: current Chrome/Edge/Safari with secure-context screen capture.
- Apple Vision Pro: Safari / visionOS with WebXR `immersive-vr`.
- Stable renderer target remains WebGL2 + WebXR.

## Known risks to verify

1. **Vision Pro video texture refresh in immersive VR.** Historical upstream report existed; later visionOS beta feedback says fixed, but the issue remains open.
2. **Camera source selection.** v0.2 relies on browser/OS camera selection. A dedicated NDI source selector belongs to the native bridge phase.
3. **Custom LAN websocket TLS.** Vision Pro must trust the local certificate.
4. **Runtime model state is local.** This version proves loading, not collaborative asset state.

Do not start a native NDI bridge until the physical Vision Pro screen/camera/virtual-NDI tests above establish that the browser/XR endpoint is useful and stable.
